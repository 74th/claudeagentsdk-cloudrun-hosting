## ADDED Requirements

### Requirement: 初回メッセージでセッションを原子的に開始する
システムは新規会話の有効な最初のメッセージと冪等キーを受け取ったときにだけセッション ID と workspace ID を割り当て、表示用セッション名、ユーザーメッセージ、最初の run、および active run 参照を原子的に保存しなければならない（SHALL）。表示用セッション名は最初のメッセージから空でない人間可読な値として決定し、後続 run によって暗黙に変更してはならない（MUST NOT）。

#### Scenario: 新規会話へ最初のメッセージを送る
- **WHEN** 利用者が未開始の新規会話へ有効なメッセージと冪等キーを送る
- **THEN** システムは名前付きセッションと最初の run を一度だけ作成し、そのセッション ID と run を返す

#### Scenario: 空の新規会話を表示する
- **WHEN** 利用者が新規会話を開いたままメッセージを送らず離れる
- **THEN** システムはセッション、run、イベント、workspace の識別子または永続レコードを作成しない

#### Scenario: 初回開始要求を再送する
- **WHEN** 同じ利用者が同じ冪等キーで初回開始要求を再送する
- **THEN** システムは既存のセッションと run を返し、空または重複したセッションを追加しない

### Requirement: セッションの全会話履歴を再取得する
システムは所有者がセッションを再訪するために、そのセッションに属する run と表示可能な会話イベントを確定順序で取得できる契約を提供しなければならない（SHALL）。複数 run のイベントは run の開始順、各 run 内の sequence と event ID の順で安定して返さなければならない（SHALL）。

#### Scenario: 複数runを持つセッションを再訪する
- **WHEN** 利用者が複数の完了済み run を持つ自分のセッション履歴を要求する
- **THEN** システムは各 run のユーザーメッセージとエージェント応答を会話順に復元できる形で返す

#### Scenario: 実行中のセッションを再訪する
- **WHEN** 利用者が active run を持つ自分のセッション履歴を要求する
- **THEN** システムは永続化済み履歴、active run とその現在状態、および増分購読を再開するための識別情報を返す

### Requirement: 期限切れのFirestoreチャットデータを扱う
Firestore 実装はセッション、run、イベントの各ドキュメントへ基準時刻から 30 日後の有効期限を保存し、期限に達したドキュメントを読み取り結果と一覧から除外しなければならない（SHALL）。物理削除が遅延しても期限切れデータを利用者へ再表示してはならず（MUST NOT）、セッション親ドキュメントの削除後に run またはイベントが無期限に残留しないよう各階層を自動削除の対象にしなければならない（SHALL）。

#### Scenario: 期限到達から物理削除まで遅延する
- **WHEN** ドキュメントの有効期限を過ぎたが自動削除処理がまだ完了していない
- **THEN** セッション一覧と履歴取得はその期限切れドキュメントを返さない

#### Scenario: セッション階層を自動削除する
- **WHEN** セッション、run、イベントの各ドキュメントがそれぞれの有効期限へ到達する
- **THEN** Firestore は各ドキュメントを手動操作なしで削除対象とし、子階層だけを無期限に保持しない

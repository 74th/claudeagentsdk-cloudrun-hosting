## ADDED Requirements

### Requirement: runの質問要求と回答を原子的に永続化する
システムは run ごとの質問要求 ID、質問内容、選択肢、複数選択可否、状態、回答、および更新時刻を永続化し、質問要求を `pending` から `answered` へ原子的に一度だけ遷移させなければならない（SHALL）。同じ冪等性キーによる回答再送は既存結果を返し、異なる回答による上書きや終端済み run への新規回答を許可してはならない（MUST NOT）。

#### Scenario: pending質問へ初めて回答する
- **WHEN** run の所有者が pending 質問要求 ID と有効な回答を送信する
- **THEN** ストアは回答を保存して質問を answered にし、待機中のジョブが取得できるよう通知する

#### Scenario: 同じ回答を再送する
- **WHEN** 同じ質問要求と冪等性キーを持つ回答が再送される
- **THEN** ストアは同じ answered 状態を返し、回答レコードまたは通知を重複作成しない

#### Scenario: 競合する回答が到着する
- **WHEN** 同じ pending 質問へ異なる回答が同時に送信される
- **THEN** ストアは最初に確定した回答だけを受理し、後続回答へ競合を返して確定値を上書きしない

#### Scenario: 終端済みrunへ回答する
- **WHEN** completed、failed、cancelled、timed_out、または dispatch_failed の run に回答が送信される
- **THEN** ストアは回答を保存せず、run が回答受付を終了していることを返す

### Requirement: 質問回答を所有者境界と保持期間に従って扱う
システムは質問要求の取得、購読、回答を run 所有者の名前空間に限定し、他の利用者へ質問内容または回答の存在を漏らしてはならない（MUST NOT）。質問要求と回答は親 run と同じ保持期限および期限切れ除外規則に従わなければならない（SHALL）。

#### Scenario: 他ユーザーの質問へ回答する
- **WHEN** 利用者が別ユーザーに属する run の質問要求 ID を指定する
- **THEN** システムは質問の存在や状態の詳細を漏らさずアクセスを拒否する

#### Scenario: 質問データの保持期限が切れる
- **WHEN** 親 run と質問要求の保持期限に到達する
- **THEN** システムは質問と回答を取得・購読結果から除外し、無期限に残留させない

### Requirement: ジョブが質問回答を切断耐性付きで待機できる
ストアは pending 質問の現在状態を取得し、回答確定を購読し、購読切断後に同じ質問要求 ID から再開できる契約を提供しなければならない（SHALL）。通知の再配信が発生しても、質問要求 ID と状態により同じ回答を一度だけ適用できる情報を返さなければならない（SHALL）。

#### Scenario: 回答通知の前に購読が切断する
- **WHEN** ジョブの回答購読が一時的に切断し、その間に回答が保存される
- **THEN** ジョブは再取得または再購読により確定済み回答を取得でき、質問を再発行しない

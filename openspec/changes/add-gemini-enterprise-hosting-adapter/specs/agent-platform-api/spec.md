## Purpose

利用者が作成した Claude Agent SDK エージェントを、Gemini Enterprise Agent Platform が規定する通常応答、ストリーミング応答、および長時間非同期実行の契約で呼び出せるようにする。

## ADDED Requirements

### Requirement: エージェントを API サーバーへ登録できる
システムは、利用者が Claude Agent SDK エージェントとホスティング設定を登録し、Agent Platform 互換のアプリケーションを生成できる API を提供しなければならない（SHALL）。設定は最大実行時間、idle timeout、セッション復元可能期間、ログレベルを変更可能にし、いずれも未指定時の既定値を持たなければならない（SHALL）。

#### Scenario: 登録したエージェントの利用
- **WHEN** 利用者がエージェントと必須設定を登録してアプリケーションを生成する
- **THEN** 生成されたアプリケーションは以後のリクエストを当該エージェントへ委譲する

#### Scenario: 必須設定の不足
- **WHEN** 利用者が必須の Session Store または Workspace Store 設定を欠いた状態でアプリケーションを生成する
- **THEN** システムは起動時に設定エラーを返し、不完全なサーバーを起動しない

#### Scenario: 実行制限を省略する
- **WHEN** 利用者が最大実行時間、idle timeout、セッション復元可能期間を指定しない
- **THEN** システムは最大実行時間30分、idle timeout 30分、セッション復元可能期間1日を適用する

### Requirement: Agent Platform の通常呼び出しを処理する
システムは Agent Platform の reasoning engine エンドポイントで通常呼び出しを受け付け、ユーザー ID、任意のセッション ID、入力メッセージを呼び出しライフサイクルへ渡し、利用したセッション ID、run ID、最終応答を JSON として返さなければならない（SHALL）。

#### Scenario: 有効な通常呼び出し
- **WHEN** ユーザー ID、既存セッション ID、1文字以上1,000文字以下の入力メッセージを含む有効な通常リクエストを受信する
- **THEN** システムは登録済みエージェントを実行し、利用したセッション ID、run ID、最終応答を成功レスポンスとして返す

#### Scenario: セッション ID を省略した通常呼び出し
- **WHEN** ユーザー IDと有効な入力メッセージを含み、セッション ID を含まない通常リクエストを受信する
- **THEN** システムは新しいセッションを作成し、そのセッション ID、run ID、最終応答を成功レスポンスとして返す

### Requirement: Agent Platform のストリーミング呼び出しを処理する
システムは Agent Platform の streaming reasoning engine エンドポイントでストリーミング呼び出しを受け付け、セッション ID、run ID、応答イベントを Agent Platform が解釈できるストリームとして順次返さなければならない（SHALL）。ストリーミング呼び出しは短時間の対話用途として提供し、切断済みストリーム自体の再開を保証してはならない（MUST NOT）。

#### Scenario: 有効なストリーミング呼び出し
- **WHEN** 有効な識別情報および入力を含むストリーミングリクエストを受信する
- **THEN** システムはセッション ID とrun IDを通知し、応答イベントを到着順に送信して完了イベントでストリームを正常終了する

### Requirement: 長時間処理を非同期実行する
システムは Agent Platform の非同期実行機構を介して長時間runを開始でき、呼び出し元がrun IDとLong-running Operation名を取得して、HTTP接続とは独立に状態確認と最終結果取得を行えるようにしなければならない（SHALL）。

#### Scenario: 非同期runを開始する
- **WHEN** 呼び出し元が有効なユーザー ID、任意のセッション ID、入力メッセージで非同期実行を開始する
- **THEN** システムはrunをバックグラウンドで継続し、追跡に必要なセッション ID、run ID、operation名を返す

#### Scenario: クライアントが切断する
- **WHEN** 非同期runの開始後にブラウザまたはフロントエンド接続が切断される
- **THEN** システムはrunをキャンセルせず、operation状態と永続化済みイベントから後で状態と結果を取得できる

### Requirement: 非同期runの状態確認とキャンセルを提供する
システムは operation名からrunの実行状態と最終結果またはエラーを取得でき、実行中runへキャンセル要求を送信できなければならない（SHALL）。キャンセル要求済みと停止完了を区別しなければならない（MUST）。

#### Scenario: 実行中runを確認する
- **WHEN** 呼び出し元が実行中runのoperation名で状態を問い合わせる
- **THEN** システムはrun IDと実行中状態を返し、保存済み主要イベントを再取得可能にする

#### Scenario: runをキャンセルする
- **WHEN** 呼び出し元が実行中runへキャンセルを要求する
- **THEN** システムは状態をキャンセル要求済みとして記録し、operationが停止したことを確認した後にキャンセル完了として記録する

### Requirement: 入力と実行障害を安全に通知する
システムはユーザー IDと1文字以上1,000文字以下の入力メッセージを要求し、入力検証エラーをクライアントエラーとして返さなければならない（SHALL）。内部例外や認証情報を応答へ露出してはならない（MUST）。

#### Scenario: 入力メッセージが長すぎる
- **WHEN** 1,000文字を超える入力メッセージを受信する
- **THEN** システムはエージェントまたはrunを開始せず、入力上限を示すエラーを返す

#### Scenario: 必須識別情報がない
- **WHEN** ユーザー IDまたは入力メッセージを欠くリクエスト、もしくは不正な形式のセッション ID を含むリクエストを受信する
- **THEN** システムはエージェントまたはrunを開始せず、修正可能な入力エラーを返す

#### Scenario: ストリーム開始後に実行が失敗する
- **WHEN** 応答イベントの送信開始後にエージェントまたは永続化処理が失敗する
- **THEN** システムは秘密情報を含まない構造化エラーイベントを送信してストリームを終了する

### Requirement: ログ出力レベルを設定できる
システムは実行時ログレベルを設定できなければならない（SHALL）。開発用DEBUGレベルではプロンプトとツール入出力を加工せず記録し、それ以外のレベルでは当該DEBUGログを出力してはならない（MUST NOT）。

#### Scenario: DEBUGログを有効にする
- **WHEN** 利用者がログレベルをDEBUGに設定してエージェントを実行する
- **THEN** システムはinvocationに関連付けてプロンプトとツール入出力を開発ログへ記録する

#### Scenario: INFOログで実行する
- **WHEN** 利用者がログレベルをINFOに設定してエージェントを実行する
- **THEN** システムは状態と識別子を記録するが、DEBUG扱いのプロンプトとツール入出力を出力しない

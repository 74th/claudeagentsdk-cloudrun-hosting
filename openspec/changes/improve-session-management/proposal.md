## Why

現在のサンプル UI は空のセッションを先に永続化し、履歴一覧では名前や更新時刻が十分に伝わらず、過去の会話を選んでも表示を完全には復元できない。セッションを会話開始時にだけ作成し、識別・再訪・自動削除までを一貫して扱えるようにする。

## What Changes

- 最初のプロンプト送信時にセッションと最初の run を開始し、未送信の空セッションには ID や Firestore ドキュメントを割り当てない。
- 最初のプロンプトから安定した表示用セッション名を設定し、現在のセッション名とセッション ID を UI に表示する。
- セッション一覧を「最終更新時刻 + セッション名」で表示し、最終更新時刻の降順に並べる。
- 過去セッションを選択したとき、そのセッションに保存された全 run の会話イベントと最新状態を復元する。
- Firestore のセッション、run、イベントへ有効期限を保存し、最終更新から 1 か月を既定の表示・保持期間として TTL による自動削除を構成する。
- UI ではセッション ID を Cloud Run 実行 ID の隣に表示し、アプリケーションのセッション ID、run ID、Cloud Run 実行 ID を区別する。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `firestore-chat-store`: 初回プロンプトに伴うセッション開始、セッション名、全履歴再取得、および期限切れデータの扱いをセッション永続化契約へ追加する。
- `realtime-chat-sample`: 遅延セッション作成、名前と更新時刻による一覧、識別子表示、および過去会話の完全な復元を UI 契約へ追加する。
- `cloud-run-job-deployment`: 名前付き Firestore database に 1 か月の TTL ポリシーを配備し、親ドキュメント削除後に run・イベントが残留しない構成を追加する。

## Impact

`Session` モデル、ChatStore/ControlClient のセッション開始・履歴取得 API、Firestore codec とクエリ、Streamlit サンプル UI、Terraform の Firestore field/TTL 構成、および各層のテストが影響を受ける。既存セッションは不足フィールドを読み取れる互換性を維持し、TTL 対象化に必要な期限フィールドは以後の更新と一度限りのバックフィルで補完する。

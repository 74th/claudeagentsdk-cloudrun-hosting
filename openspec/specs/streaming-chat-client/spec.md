# streaming-chat-client Specification

## Purpose

フロントエンドの種類に依存せず、会話セッションと非同期 run を開始し、保存済みおよび新着の応答イベントを一つのストリームとして利用できるようにする。

## Requirements

### Requirement: フロントエンド非依存で会話runを開始する
共通チャットクライアントは、ユーザー ID、プロンプト、および任意の既存セッション ID を受け取り、新規または既存セッションで非同期 run を開始し、セッション ID と run ID を呼び出し元へ返さなければならない（SHALL）。同じ開始要求が再送された場合に run を重複作成しないため、呼び出し元が冪等性キーを指定できなければならない（SHALL）。

#### Scenario: 新しい会話を開始する
- **WHEN** 呼び出し元がユーザー ID、プロンプト、冪等性キーを指定し、セッション ID を指定せずに開始する
- **THEN** クライアントは新しいセッションと最初の run を開始し、そのセッション ID と run ID を返す

#### Scenario: 既存の会話を継続する
- **WHEN** 呼び出し元がアクセス可能な既存セッション ID とプロンプトを指定する
- **THEN** クライアントはそのセッションに新しい run を開始し、同じセッション ID と新しい run ID を返す

#### Scenario: 開始要求を再送する
- **WHEN** 同じユーザー、セッション、および冪等性キーを持つ開始要求が再送される
- **THEN** クライアントは同じ run を返し、別の run を重複作成しない

### Requirement: runのイベントを連続したストリームとして提供する
共通チャットクライアントは、run に保存済みのイベントと購読開始後の新着イベントを順序どおりの一つのストリームとして提供し、各イベントを一度だけ呼び出し元へ渡さなければならない（SHALL）。ストリームは終端イベントまたは run の終端状態を通知した後に完了しなければならない（SHALL）。

#### Scenario: 購読前にイベントが保存されている
- **WHEN** 呼び出し元が、すでに複数のイベントを保存済みの run のストリームを開始する
- **THEN** クライアントは保存済みイベントを順番に返した後、カーソル以後の新着イベントを同じストリームで返す

#### Scenario: 保存済み取得と新着購読が重なる
- **WHEN** 保存済みイベントの取得中に同じイベントが購読結果にも現れる
- **THEN** クライアントはイベント識別子に基づいて重複を除外し、そのイベントを一度だけ返す

#### Scenario: runが完了する
- **WHEN** run の成功、失敗、またはキャンセルを表す終端情報を受信する
- **THEN** クライアントは終端情報を呼び出し元へ渡してストリームを完了する

#### Scenario: 一時的な購読エラーが発生する
- **WHEN** イベント購読が一時的なエラーで中断する
- **THEN** クライアントは最後に配信済みのカーソルから再接続し、既配信イベントを重複させずに配信を継続する

### Requirement: CLIでストリーミング動作を検証する
CLI サンプルは、リリース設定、ユーザー ID、プロンプト、および任意のセッション ID をコマンドラインから受け取り、共通チャットクライアントで run を開始して、識別子と各応答イベントを到着順に標準出力へ逐次出力しなければならない（SHALL）。終端状態が失敗またはキャンセルの場合、または開始不能な設定エラーの場合は非ゼロの終了コードを返さなければならない（SHALL）。

#### Scenario: CLIから応答を確認する
- **WHEN** 利用者が有効なリリース設定、ユーザー ID、およびプロンプトを指定して CLI を実行する
- **THEN** CLI はセッション ID と run ID を表示し、バッファーへ全件蓄積してからではなく各イベントを受信するたびに標準出力へ表示する

#### Scenario: CLIから既存セッションを継続する
- **WHEN** 利用者が前回表示されたセッション ID と新しいプロンプトを指定する
- **THEN** CLI は既存セッションで run を開始し、新しい応答イベントを逐次表示する

#### Scenario: runが失敗する
- **WHEN** CLI が監視している run が失敗の終端状態になる
- **THEN** CLI は安全な失敗情報を標準エラーへ表示し、非ゼロの終了コードで終了する

### Requirement: フロントエンドが共通イベント表現を利用する
共通チャットクライアントは、エージェント本文、ツール開始、ツール完了、進捗、終端状態をフロントエンド固有型に依存しないイベントとして提供しなければならない（SHALL）。未知のイベント種別を受信してもストリーム全体を失敗させてはならない（MUST NOT）。

#### Scenario: 複数種別のイベントを受信する
- **WHEN** run がエージェント本文、ツール進捗、および終端イベントを保存する
- **THEN** 呼び出し元は各イベントの種別、識別子、run ID、および表示可能な内容を共通表現から取得できる

#### Scenario: 未知のイベント種別を受信する
- **WHEN** クライアントが未対応のイベント種別を受信する
- **THEN** クライアントは未知イベントとして安全に呼び出し元へ渡すか無視し、後続イベントの配信を継続する
